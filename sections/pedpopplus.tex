\section{$\pedpopplus$}

$\pedpopplus$ is a modification of $\pedpop$ in which three extra rounds of communications are added.
This protocol could either be used as a DKG or as a Key Resharing scheme.
We depict the key generation protocol in Figure~\ref{fig:pedpopplus} and
key resharing in Figure~\ref{fig:pedpopplus-reshare}.

We require the online-extractable non-interactive zero-knowledge proof (NIZK) for the relation described in
Section~\ref{def:online-extractable}.

\subsection{Key Generation}\label{sec:key-generation}
In Round 0, a participant performs necessary checks, then picks a random session identifier and broadcasts it.
It then receives the broadcast session identifiers from its peers and hashes all identifiers into one single string in Round 1.
The participant picks $\thresh$ random coefficients. Each coefficient $a$ is committed to by computing $g^a$.
The vector of commitments is hashed and sent to all the peers.
Still in Round 1, the participant gives a proof of knowledge of $\alpha$ such that $A_0 = g^\alpha$ using the non-interactive zero-knowledge proof system.
In Round 2, the participant receives the hash values from its peers, stores them, and broadcasts the commitment vector along with the proof $\pi_k$.
In Round 3, each participant evaluates the polynomial generated by the picked coefficients.
The number of evaluations is equal to the number of participants currently contributing to the protocol.
It then verifies the correctness of the signature and the well-formedness of the received hash value then privately shares each computed polynomial evaluation with the corresponding peer participant.
Round 4 receives the evaluations and verifies their correctness, then computing the master verification key and the private signing key share.
Finally, if all the checks pass, then a success string is broadcast.
In Round 5, each participant collects $n$ success strings,
else the participant aborts.

\subsection{Key Resharing}\label{sec:key-resharing}
Key Resharing using $\pedpopplus$ is similar to key generation,
with the exception that participants distribute sub-shares of their secret share,
as opposed to a random value, as is the case for key generation.

\paragraph{Allowing New Joiners}
It is possible to allow new participants to join the coalition of signers,
in such a way that these participants also contribute to the total randomness of the shares,
while keeping the original secret key the same.

We likewise show this approach in Figure~\ref{fig:pedpopplus-reshare}.

In Round 1, we distinguish two cases: if the participant running the protocol is part of the new joining participants, then it simply sets the first coefficient (denoted $\alpha$) to zero; otherwise, it linearizes its old share of secret key using
Lagrange coefficients generated for common parties between old and new participants sets.
More specifically, the function $\linearize_k(\oldsk, I)$ computes the product
\[
\linearize_k(\oldsk, I)\coloneqq \oldsk \cdot \prod_{\substack{i\in I\\ i\neq k}} \frac{i}{i-k}
\]

In Round 4, the computed verification key is checked to match the same old public key given as input to the protocol.
Checking such invariant is due to the fact that honest new participants shall not affect the value of the old verification key as their initial private shares are set to zero.

\procedure{$\KeyGen_0(k, t, n)$}{

\procedure{$\KeyGen_1(\sid_1, \ldots, \sid_n)$}{

A_0 \gets g^{\alpha} \\
\pcfor i \in \set{\tcor} \pcdo \\
\quad A_i \gets g^{a_i} \\
C_k \gets (A_0, \ldots, A_{\tcor})\\
\color{red} h_k \gets \HashCom(\sid, k, C_k) \\
\color{red} \gamma_k \gets (\sid, k, C_k[0]) \\

\procedure{$\KeyGen_3(\{C_i, \pi_i\}_{i\in\set{n}})$}{
\pcfor j \in \set{n} \\

\pcfor i \in \set{n}, i \neq k \\
\color{red} \quad \gamma_i \gets (\sid, k, C_i[0]) \\

\color{red} \quad \require \HashCom(\sid, i, C_i) = h_i\\
\quad \send(i, f_k(i)) \\
}
\procedure{$\KeyGen_4(\{f_i(k)\}_{i\in\set{n}})$}{
\pcfor i \in \set{n}, i \neq k \\
\quad \require g^{f_i(k)} = \prod_{j=0}^{\tcor} C_i[j]^{k^j} \\
\color{red} \text{(No derivation for participants public key)}\\

\color{red} \pcfor i \in \set{n} \\
\color{red} \quad \require b_i = (\success, \sid) \pccomment{else abort} \\
